# Запуск
1. файл `.env.example` переименовать в `.env`
2. Первоначально на ПК должен быть докер
3. В корневой папке проекта(где находится `docker-compose.yml` файл) через консоль прописать `docker compose up -d --build`
4. После запуска для доступа к апи нужно перейти по http://localhost:8080/docs
# Описание системы ролей
## Роли
**Администратор** и **Пользователь**
доступ разрешён, если `user.role_id <= required_role`
## Аутентификация
JWT (access + refresh) в **HttpOnly cookies**
**Middleware** `user_middleware`:
	читает токены, валидирует, при необходимости обновляет access
	загружает пользователя из БД и кладёт в `request.state.user`
## Проверка авторизации и прав
`get_user` – возвращает пользователя или `None`
`get_authorized_user` – требует авторизации, иначе 401
`auth_check` – дополняет `get_authorized_user`:
	проверяет наличие декоратора `@role_required` у эндпоинта
	сравнивает `role_id` пользователя с требуемым значением
## Декоратор `@role_required(role)`
Вешается на эндпоинт, устанавливает атрибут `_role_required`
При вызове `auth_check` автоматически применяет проверку
## Примеры ограничений

| Эндпоинт                    | Доступ                                                      |
| --------------------------- | ----------------------------------------------------------- |
| `/api/auth/*`               | публичные                                                   |
| `/api/user/me/*`            | только авторизованные                                       |
| `/api/content/`             | только авторизованные; фильтрация контента по `role_access` |
| `/api/content/admin/change` | только администраторы (`@role_required(1)`)                 |
## Контроль данных
- В `/api/content/` возвращаются только элементы, у которых `role_access >= user.role_id`
